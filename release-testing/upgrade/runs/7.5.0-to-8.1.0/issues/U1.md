Unread notifications are lost when the opencloud container is recreated (e.g. upgrade 7.5.0 → 8.1.0)

### Steps
1. opencloud-compose, `opencloudeu/opencloud-rolling:7.5.0`.
2. User A shares a file with user B. B's bell shows 1 unread notification.
3. Upgrade to 8.1.0 (`docker compose up -d` with the new tag, same volumes).
4. Log in as B.

### Expected
The unread notification is still there.

### Actual
0 notifications for every user, in the API and in the bell.

### Cause
`USERLOG_STORE` defaults to `memory`. opencloud-compose sets neither `USERLOG_STORE` nor `OC_PERSISTENT_STORE`, so
notifications live only in memory and every container restart drops them — not only an upgrade.

### Proposal
Configure a persistent store for userlog in opencloud-compose (e.g. `nats-js-kv`), or document it in the upgrade notes.

Found by the agent-driven upgrade test 7.5.0 → 8.1.0.
