Search: KQL `mtime:<date>` alone returns HTTP 500 "can not compile the query"

### Steps
`REPORT /dav/spaces/` with `<oc:pattern>mtime:2022-09-01</oc:pattern>` (also quoted).

### Expected
Files modified on that day, or a 400 for an unsupported operator.

### Actual
HTTP 500 "can not compile the query". Combined with another term (`name:"x*" mtime:2022-09-01`) the date is silently
ignored. The compiler skips dates with the `:` operator; same code in v7.5.0 and v8.1.0. No UI path triggers it.

Found by the agent-driven upgrade test 7.5.0 → 8.1.0 (also present on 7.5.0).
