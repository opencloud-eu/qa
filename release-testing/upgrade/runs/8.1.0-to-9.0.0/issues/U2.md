Enabling guest links on an upgraded config stops opencloud; the #3609 migration note names the wrong setting

### Steps
1. Install `opencloudeu/opencloud-rolling:8.1.0` with opencloud-compose (`opencloud init` writes `opencloud.yaml`).
2. Upgrade to `opencloudeu/opencloud:dev` (9.0.0+dev), same volumes. It starts (guest links are off by default).
3. Set `OC_ENABLE_GUEST_LINKS=true` and recreate the container, without running `opencloud init --diff`.

### Expected
opencloud keeps running. If guest links cannot start, only that feature is unavailable, with a clear error.
The upgrade notes name what an existing install has to add.

### Actual
```
auth-guest: unable to register services: rgrpc: grpc service authprovider could not be started,:
  guestlinks: service_account_id must not be empty
opencloud: Failed service 'auth-guest' (5.99 failures of 5), restarting: false   (level fatal)
```
opencloud exits, the container restarts in a loop, `status.php` never answers.

### Cause
`opencloud init` on main writes a new `auth_guest.service_account` section (`opencloud/pkg/init/structs.go`), but
only into new configs. The migration note of #3609 asks for `AUTH_GUEST_JWT_SECRET`, which is no longer required
(`env:"OC_JWT_SECRET;AUTH_GUEST_JWT_SECRET"`, session key derived via HKDF since #3671). The service account is not
mentioned.

### Workaround
`opencloud init --diff` with the new image and apply `opencloud.config.patch` (verified), or set
`AUTH_GUEST_SERVICE_ACCOUNT_ID` / `AUTH_GUEST_SERVICE_ACCOUNT_SECRET` (from the code, not verified).

### Proposal
- Fix the migration note / release notes: name `opencloud init --diff` and the service account.
- Fall back to the shared service account, or fail only the guest-links feature instead of the whole server.

Found by the agent-driven upgrade test 8.1.0 → 9.0.0-dev.
