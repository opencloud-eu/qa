Thumbnail of a truncated PNG with processor=fit returns 500 instead of 404

### Steps
1. Upload a truncated PNG (valid header, cut-off data).
2. Request `?preview=1&x=320&y=320&processor=fit` (what the web tiles view asks for).

### Expected
404, as for any source the generator cannot read (`services/webdav/README.md`), and as with `processor=thumbnail`.

### Actual
500 "could not generate thumbnail". Log: `generator returned status 500: failed to encode image`.
The web tiles view shows a generic icon, so users don't see an error.

### Note
Reproduced twice via API and twice in web on 9.0.0+dev (push-based thumbnails, #3397). Low severity.

Found by the agent-driven upgrade test 8.1.0 → 9.0.0-dev.
