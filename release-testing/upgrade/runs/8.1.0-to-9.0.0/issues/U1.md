Unread notifications are still lost when the opencloud container is recreated (upgrade 8.1.0 → 9.0.0-dev)

Follow-up of the same finding in the 7.5.0 → 8.1.0 upgrade test (`release-testing/upgrade/runs/7.5.0-to-8.1.0/issues/U1.md`).

### Steps
1. opencloud-compose, `opencloudeu/opencloud-rolling:8.1.0`.
2. User A shares a file with user B, an admin adds B to a project space, A mentions B in a collaborative markdown file.
   B's bell shows the unread notifications.
3. Upgrade to `opencloudeu/opencloud:dev` (9.0.0+dev) with `docker compose up -d`, same volumes.
4. Log in as B.

### Expected
The unread notifications are still there.

### Actual
0 notifications for every user, in the API (`/ocs/v2.php/apps/notifications/api/v1/notifications`) and in the bell.
New notifications after the upgrade work.

### Cause
`USERLOG_STORE` still defaults to `memory` (`services/userlog/pkg/config/defaults/defaultconfig.go`). opencloud-compose
sets neither `USERLOG_STORE` nor `OC_PERSISTENT_STORE`, so every container restart drops notifications, not only an upgrade.

### Proposal
Configure a persistent store for userlog in opencloud-compose (e.g. `nats-js-kv`), change the default, or document it in
the upgrade notes.

Found by the agent-driven upgrade test 8.1.0 → 9.0.0-dev.
