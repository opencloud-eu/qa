Guest invited to a whole project space can't open it in the web UI

### Steps
1. Enable guest links (`OC_ENABLE_GUEST_LINKS=true`) and a mail server.
2. As a space manager, invite an email address to a project space via Graph
   (`POST /graph/v1beta1/drives/<space-id>/root/invite` with an email recipient). The web Members panel offers no guest
   for an email address, so the API is the only way.
3. Open the link from the invitation mail in a fresh browser.

### Expected
The guest sees the project space, or Graph refuses email recipients on a space root.

### Actual
- Redeem returns 200 and the session can read the whole space via WebDAV by space id.
- `GET /graph/v1beta1/me/drive/sharedWithMe` returns an empty list for the guest, and web shows
  "An error occurred while opening the invitation — The shared item is no longer available".
- Reopening the used link starts a renew with a valid session, so the backend mails a PIN, but the page has no PIN
  field (the mail says to enter it there). Each reopen uses one of the 5 daily renewals.

A guest share of a single file inside a project space works.

### Note
Reproduced twice on 9.0.0+dev (web 8.2.0), after an upgrade from 8.1.0. A gap in the new feature, not caused by the
upgrade. Likely component: web and/or graph (`sharedWithMe` does not list a guest's space membership).

Found by the agent-driven upgrade test 8.1.0 → 9.0.0-dev.
