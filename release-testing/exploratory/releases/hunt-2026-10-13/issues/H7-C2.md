After renaming or deleting a folder in search results, its descendants keep a stale path; actions on them fail

## Steps to reproduce
1. Search so that a folder and a file inside it are both listed.
2. Rename (or delete) the folder from the results.
3. Rename / open / delete the child.

## Actual
Rename: the child keeps the old path, renaming fails ("Failed to rename", MOVE 404). Delete: the child stays listed; opening shows "Resource not found", deleting shows "Failed to delete".

## Expected
Descendants are updated or removed.

## Cause (web v8.1.0)
`packages/web-app-files/src/composables/actions/files/useFileActionsRename.ts:54-104` updates only the renamed resource; the search list (`components/Search/List.vue:463-469`) holds descendants with absolute paths. Delete likewise.

## Fix idea
After rename/move/delete of a folder, rewrite or drop store resources below the old path (or re-run the search).

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H7-C2, reproduced 2/2 rename, 2/2 delete.
