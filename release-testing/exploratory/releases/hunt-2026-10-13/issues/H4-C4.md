Owner opening their own file-drop link is not redirected to the folder (fileId holds the link token)

## Steps to reproduce
1. alan creates a "Secret File Drop" link on a folder.
2. While logged in, open `/s/<token>` and enter the password.

## Actual
alan lands on `/files/upload/<token>?fileId=<token>` (anonymous upload page); `getPathForFileId` fails (401 PROPFIND `/dav/meta/<token>`). A folder link instead redirects to the internal folder.

## Expected
Redirect to the internal folder as `FilesDrop.vue` intends.

## Cause (web v8.1.0)
`packages/web-runtime/src/pages/resolvePublicLink.vue:196-200` pushes `fileId: publicLinkSpace.fileId`, which falls back to the token; consumer `packages/web-app-files/src/views/FilesDrop.vue:208-217`.

## Fix idea
Use `loadedSpace.fileId`.

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H4-C4, reproduced 2/2.
