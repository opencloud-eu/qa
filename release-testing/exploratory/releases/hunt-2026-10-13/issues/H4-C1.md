Public link role dropdown keeps showing the new role after the update failed

## Steps to reproduce
1. Folder with a "Can edit" link; open sidebar → Share.
2. Change the role to "Can view" while the PATCH fails (network / 500).

## Actual
Toast "Failed to update link", but the row shows "Can view"; the server still has `edit`. The owner believes the link is read-only while anonymous users can still edit.

## Expected
The row keeps the real role.

## Cause (web v8.1.0)
`packages/web-app-files/src/components/SideBar/Shares/Links/ListItem.vue:105,111-121` — local `currentLinkType` is set before the request and never reset.

## Fix idea
Derive the value from `linkShare.type` (computed) or revert on failure.

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H4-C1, reproduced 2/2.
