Dragging an unselected item also moves every item that was selected before

## Steps to reproduce
1. In a folder with `a.txt`, `b.txt` and a folder `target` (table view), click the row of `a.txt` so that only it is selected.
2. Drag `b.txt` (not selected) and drop it on `target`.

## Actual
`a.txt` **and** `b.txt` are moved into `target`, without any notice (confirmed via WebDAV). Natural variant: right-click → Rename on one file (right-click selects it), then drag another file into a folder — the renamed file moves along.

## Expected
Only the dragged item is moved; dragging an unselected item replaces the selection (common file-manager behaviour).

## Cause (web v8.1.0)
`packages/web-pkg/src/composables/resources/useResourceViewDrag.ts:32-38` — `dragStart` calls `toggleSelection(resource.id)`, which adds the dragged item to the existing selection; `GenericSpace.vue:441-506` (`fileDropped`) then moves all `selectedResources`.

## Fix idea
If the dragged item is not selected, replace the selection with it (`setSelection([resource.id])`).

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H1-C1, reproduced 3/3.
