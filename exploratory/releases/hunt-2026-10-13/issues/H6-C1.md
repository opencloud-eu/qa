App URL of a file opened by another user with access shows a raw TypeError

## Steps to reproduce
1. alan shares a folder with lynn (Can edit), opens a `.md` in the Text Editor (or an image in Preview) and copies the URL.
2. lynn opens that URL.

## Actual
The app area shows only `Cannot read properties of undefined (reading 'webDavPath')`. `/f/<id>` works for her. Variant: `/preview?fileId=<png id>` shows `… of null (reading 'webDavPath')`, also for the owner.

## Expected
The file opens (the URL has a fileId she can access), or a clear "not found / no access" message.

## Cause (web v8.1.0)
`packages/web-pkg/src/components/AppTemplates/AppWrapper.vue:351-355` falls back to the fileId only when the path part is empty, not when it can't be resolved (`useAppDefaults.ts:52-60` leaves the space undefined); preview skips `loadResourceTask` (`AppWrapper.vue:472-507`).

## Fix idea
Fall back to resolving by fileId when the drive alias can't be resolved, and show a proper error otherwise.

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, lynn, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H6-C1, reproduced 2/2.
