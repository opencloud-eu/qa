A live notification disappears again when a slower initial notifications request finishes

## Steps to reproduce
1. Reload while the notifications list request is slow.
2. Meanwhile another user shares something with you (SSE notification appears).
3. Wait for the list request to finish.

## Actual
The older list response replaces the list; the live notification is gone (still on the server) until reload.

## Expected
Live notifications are merged with the fetched list.

## Cause (web v8.1.0)
`packages/web-runtime/src/components/Topbar/Notifications.vue` `fetchNotificationsTask` assigns `notifications.value = data`, dropping SSE items; SSE items are not deduplicated and the list uses `:key="index"`.

## Fix idea
Merge by `notification_id` instead of replacing.

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, mary, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H9-2, reproduced 2/2.
