Upload "Keep both" renames a file to the name of another file in the same upload; that file is silently lost

## Steps to reproduce
1. Folder contains `c.txt`.
2. Upload two files at once: `c.txt` and `c (1).txt`.
3. In the conflict dialog choose Keep both.

## Actual
Both uploads target `c (1).txt`; one TUS POST gets 409 and is retried; the result is `c (1).txt` = content of the new `c.txt`. The user's own `c (1).txt` is gone, while the panel says "2 files uploaded".

## Expected
`c.txt` (old), `c (1).txt` (uploaded) and `c (2).txt` (renamed upload).

## Cause (web v8.1.0)
`packages/web-app-files/src/helpers/resource/actions/upload.ts:171-175` — `resolveFileNameDuplicate` checks only the files already in the folder, not the other files of the same batch (same for folders, line 188).

## Fix idea
Pass the names of the batch (and names already assigned in the loop) to `resolveFileNameDuplicate`.

## Environment
OpenCloud 8.1.0+85466427 (rolling), web 8.1.0, Chromium (Playwright), alan, desktop. Found in the exploratory bug hunt of 2026-10-13 (opencloud-eu/qa, `exploratory/releases/hunt-2026-10-13`), finding H2-3, reproduced 2/2.
